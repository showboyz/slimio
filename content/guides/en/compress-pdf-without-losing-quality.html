"File must be under 2MB." "Maximum upload size: 100KB." "Attachment too large." Most people meet PDF compression at that moment and grab the first tool they find — and then discover that the result is readable only if you squint. It doesn't have to be. This guide explains what makes a PDF big, what a good compressor changes and what it leaves alone, and how to reach a fixed size without wrecking the document.

What takes up space inside a PDF

A PDF is a container. The pieces inside it are very different in size:

  • Text is stored as characters plus the shapes of the fonts used. A full page of text costs only a few kilobytes.
  • Fonts can be big if a document embeds whole font files. A good compressor keeps only the letters that are actually used (font subsetting).
  • Vector graphics — tables, lines, charts drawn in a design app — are drawing instructions, also small.
  • Images — photos, logos, and every page of a scan — are usually 80–99% of the file. A single phone photo can be 3–5MB on its own.

So compressing a PDF well is mostly about one thing: making the images inside it as small as they can be without looking worse at the size they are shown, and leaving the text alone.

Choosing a resolution for the images

Image resolution in a PDF is measured in dots per inch (dpi) at the size the image is printed on the page. Choosing it is the main quality decision:

SettingImage resolutionGood for
Smallest72 dpiUpload forms with tight limits, documents read only on screen
Balanced150 dpiEmail, sharing, most uploads — photos still look good on a laptop or phone
High quality300 dpiDocuments that will be printed

Because text is untouched, even the smallest setting keeps typed text perfectly readable; only photos and scanned pages lose detail. For a scanned page, 150 dpi is usually the lowest resolution at which small print stays comfortable to read.

Hitting an exact limit: 100KB, 200KB, 1MB

When a form gives a hard limit, the goal changes from "smaller" to "the best quality that still fits". The method that works:

  1. Check whether it already fits. Many PDFs exported from Word or HWP are already under 100KB. Don't touch them.
  2. Compress the images only, starting with the lighter setting. If the result fits, stop — text is still crisp.
  3. Only if it still doesn't fit, render the pages as images, trying the sharpest resolution first and stepping down until the file fits.

This is exactly what the 100KB, 200KB, 500KB and 1MB pages do, so you don't have to guess settings. As a rough guide to what is realistic:

Five things that shrink a PDF more than any setting

  1. Upload only the pages asked for. A form that wants "proof of address" doesn't need the 12-page agreement. Use Remove pages or Split first.
  2. Scan at 150 dpi, in grayscale. A 600 dpi colour scan of a black-and-white letter is mostly wasted data.
  3. Shrink photos before putting them in a document. A 4000-pixel phone photo shown 8 cm wide on a page is far bigger than it needs to be.
  4. Export, don't print-to-PDF from a photo. A PDF exported from a word processor keeps text as text; a photo of a printed page turns it into an image.
  5. Split long documents into two or three files if each upload slot has its own limit.

Privacy: where does the file go?

Some compression has to happen on a server — font subsetting and the most efficient image re-encoding use Ghostscript, which doesn't run in a browser. SlimIO's sharp mode sends the file over HTTPS, compresses it and deletes it right away; nothing is stored. The private mode does the image compression inside your browser instead, so the file never leaves your device; it can't subset fonts, so text-only PDFs shrink a little less. Files over 50MB always use the private mode.

Quick answers

  • "Under 2MB" for email or a portal: the compressor with the balanced setting is almost always enough.
  • "Under 100KB" for a job or exam form: use the 100KB page and upload only the pages required.
  • A PDF that won't go below the limit: look at what's inside. If it's a long scan, split it; if it's photos, shrink them at the source.
