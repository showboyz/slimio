# Naver SmartEditor helpers

Scripts for posting the drafts in `marketing/naver/` through Naver's SmartEditor with `orca computer`, in a Chrome window of our own. They used to live only in a session scratchpad. macOS deleted them along with other old files in `/private/tmp` (2026-10-27), so they are kept here now.

- `chunk.py <draft.html> <dir>`: splits a draft at each `<!--IMG:…-->` mark into `cN.html` and `cN.txt` paste chunks, and copies `setclip.js` into the folder. Tables get inline borders, a tinted header row and column widths that follow the text length, because the editor turns a bare table into borderless equal-width cells (it keeps inline `border`, `background-color`, `color`, `width %` and `text-align`; tested 2026-10-29).
- `post.sh <win> <dir> <title> <small-img|-> <img1> [img2 …]`: types the title, then for each image uploads it with the editor's 사진 button (`img.sh`) and pastes the matching chunk as rich text (`setclip.js`). With a small-img name, `small.sh` sets that image to 작게 and centres it.
- `finish11.sh <win> <day> <tag…>`: opens the 발행 panel, adds the tags (`tag1.py` stops on the first one that fails), schedules November `<day>` at 08:00 (`sched11.sh`), checks the panel, and then publishes. Pass tags as literal words. zsh does not split an unquoted `$TAGS`.
- `finish.sh <win> <YYYY-MM-DD> <HH> <tag…>` / `sched.sh <win> <YYYY-MM-DD> <HH>`: the same for any month and hour (the 19:00 posts). sched.sh clicks '다음 달' once per month ahead of this one.
- `tblfix.py <win> <draft.html>`: in a post open in the editor, gives every table the editor's own 표2 style (grid, grey header), for posts pasted before chunk.py styled tables. It finds a cell by a text that occurs once in the post (Chrome find), clicks it where `hl.cjs` sees the orange match highlight in a screenshot, then picks 표 스타일 → 표2 and checks it. `tblfix_sched.py <win> <YYYY.MM.DD>…` does this for scheduled 08:00 posts and saves each one with its schedule unchanged, or leaves it unsaved if any table or the 발행 panel check fails.
- `guard.sh` before each step and `guard.sh done` after it: fails if the screen is locked or someone used the keyboard or mouse since the last step (120 s without input before the first one). It counts keyboard and mouse events only, because a plugged-in game controller resets the system idle time several times a second.
- `clipsave.js <dir>` / `cliprestore.js <dir>` (run with `osascript -l JavaScript`): back up every type on the clipboard before posting and put it back afterwards. clipsave creates `<dir>` and stops with an error if it can't write the backup.
- `k.sh <win> <action…>`: brings the window back, checks that Chrome is frontmost, and only then sends the action. `c.py` runs one action and prints the matching lines of the accessibility tree. `nav.py` sets the address bar.
- Since the orca update of 2026-11-10, Chrome's find bar and its '사이트에서 나가시겠습니까?' dialog are windows of their own. While the find bar is open the editor window's tree can be just the bar, and clicking its 검색 바 닫기 through the editor window does nothing. `tblfix.close_find(before)` clicks it in the bar's own window, one that appeared after my Cmd+F (Esc would scroll the editor back to its old caret). `leavedlg.sh [press]` finds the leave dialog through System Events (orca does not list it), and `leave_unsaved()` and `win_close.sh` answer 나가기 there only when it was not open before their own step. ctaoff.py uses close_find; ctains, lnkins, ctadel, pubnow and tblfix still press the old way and need the same change before they are used again. k.sh now prints `FAIL <code>` when orca refuses an action (the old printout contained 'ok' and passed tblfix.k's check).
- Also since that update: a background click on a `<select>` is refused, so sched.sh opens the 시간/분 dropdowns with `--restore-window`; and the 사진 button's file dialog is a sheet orca cannot focus, so `img.sh` now puts the file on the clipboard as Finder's Copy does (`fileclip.js`) and pastes it. The editor uploads it under its own file name (tested 2026-11-12 on #78–#81).
- `resched.py <win> <NN> <YYYY.MM.DD> <HH> <YYYY-MM-DD> <HH>`: moves a reserved post to another date and hour. It checks the title and the 발행 panel before and after `sched.sh`, and leaves without saving if anything is off (used 2026-11-12 to move #26–#29 to 12/2–12/3).
- `../top.py <query>…`: the top 6 blog-tab results for a query (moved from the 11/10 scratchpad).
- `win_open.sh <url>` / `win_close.sh <win>`: open a Chrome window of our own (waits for guard.sh, prints the new window id) and close it again by its 닫기 버튼, answering 나가기 if Chrome asks. Never use them on a window we did not open.
- Taking the SlimIO button out of reserved posts (HANDOFF 2-58, 2-62): `ctaoff.py <win> <NN> <YYYY.MM.DD> <HH>` does one post; `ctaday.sh <HH:MM> [count]` waits for that time and does the next `count` posts from `ctaday/res.txt` that are not in `ctaday/done.txt`, each checked by a second ctaoff run, logging to `ctaday/log.txt`. It runs once, so start it again for the next day. `listres.py <win> <out>` writes the editor's 예약 발행 list ("time, title, draft NN"); `recent.py <n>` prints where the n newest posts rank when their own title is searched on Naver. These moved here from the scratchpad on 2026-11-10, after the midnight clean-up of `/private/tmp` deleted close.sh.

Coordinates assume the editor window size used so far. The full step-by-step and the pitfalls are in HANDOFF.md (2-28 to 2-31).
